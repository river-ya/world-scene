# v0.4.0 厨房使用 studio_b1 相机模板

用户已确认使用 studio_b1 的视角。本次只提交一个 `studioview` 推理任务，用同一张厨房图对比 70462、70680。不重新生成原 studio 房间，不继续其余七例，也不训练。

## 1. 固定与改变的条件

| 条件 | 本次设置 |
|---|---|
| 图片与文本 | 与厨房 70462 完全一致；完整基线输入摘要强制核对 |
| seed / 权重 / 精度 / offload | 保持 seed 0 及现有模型设置 |
| 分辨率 / 采样相机数 | 704×480 / 24 |
| 相机位姿 | 完整使用固定官方 examples/5.json，即 studio_b1 |
| 内参 | 使用 studio 的目标内参，按厨房图片裁剪逆算输入内参 |
| 输入锚点 | image_index 9；视频约第 9 秒、第 135 帧 |
| 归一化 | 上游原生按轨迹归一化；不启用 v0.3.0 固定尺度兼容层 |
| 相对输入最大旋转 / 归一化平移 | 约 26.85° / 0.557 模型单位；不是米 |

这是整套相机模板对照，同时改变位姿、内参、输入锚点；不能解释为仅改变转角的单因素消融。相机并非厨房真实标定，原 studio 成功不保证新图成功。新实验协议发布为 v0.4.0，旧包与结果保持不变；上游源码、模型结构、依赖、权重和数据选择没有变化。

仍使用单张 4090、96G 内存、8 CPU，按旧例约一小时作预算参考，实际运行时间待测。30 项本地测试和相机 CPU 检查不代替 GPU 视觉验收。

先查看旧任务。当前对照不要求取消其他作业；使用共享资产回执的旧版本任务结束后，再刷新回执。保持 96G：旧 64G 已实际 OOM，切换相机模板不等于模型内存变小。

```bash

```

旧版本任务结束后执行：

```bash
(

  if [[ ! -e world_scene-v0.4.0 ]]; then
```

预检应看到 `OFFLINE_PREFLIGHT_OK`、两行 `STUDIO_CAMERA_MATCH_OK`、`STUDIO_EXPORT_SCALE_OK` 和 `STUDIOVIEW_INPUT_OK`。相机检查在 CPU 上调用固定上游的真实张量函数及密集插值，不加载模型权重。若失败，停止提交并保留完整报错，不绕过检查。

## 8. 视觉比较与清理

本次输入锚点在视频约第 9 秒、第 135 帧；旧 70462 和小视角 70680 的输入锚点约在第 3 秒、第 45 帧。先对齐这些输入锚点，检查地板是否被新增桌台遮住，橱柜、窗户、灶台是否保留；不要简单按相同播放秒数比较。再看全片新增可见区域、连续视差及几何，记录漂浮碎片、闪烁、穿透、表面断裂。最大转角约 27° 不保证必然补出足够区域或改善质量。

保留旧 70462、小视角 70680 和新结果，即使新版仍失败。不要覆盖原始视频、删掉失败记录或把单次改善说成大范围补全成功。本次不训练、不换模型、不改文本、不搜索随机种子。

作业正常退出自动删除它自己的临时输入。若存在异常退出遗留，只清理已结束任务的临时目录。工具在用户仍有任何排队/运行作业时拒绝执行删除。
