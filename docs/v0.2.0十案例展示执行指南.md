# v0.2.0 十案例展示执行指南

## 1. 范围与案例

本版沿用 FlashWorld 权重、精度、seed=0、T5/VAE 卸载和 96G 主存。增加可复现展示输入及单卡数组入口。论文依据为 [FlashWorld](https://arxiv.org/abs/2510.13678) 的单图/文本到 3DGS 生成任务及 [WorldScore](https://arxiv.org/abs/2504.00983) 的条件与相机控制评估组织方式；本项目不是官方完整 WorldScore 分数复现。

| 索引 | 展示内容 | 安排 |
|---|---|---|
| 0 | 客厅，官方图文和轨迹 | 复用 v0.1.3 的 room_b1-70288-0 |
| 1 | 音响房间，官方图文和轨迹 | 复用 v0.1.3 的 studio_b1-70387-3 |
| 2 | ws-indoor-000：开放厨房 | 新推理，先作相机适配试跑 |
| 3 | ws-indoor-001：客厅/餐区 | 新推理 |
| 4 | ws-indoor-002：废弃走廊 | 新推理 |
| 5 | ws-indoor-003：图书馆 | 新推理 |
| 6 | ws-indoor-004：办公室 | 新推理；源图有渲染质感 |
| 7 | ws-indoor-005：岛台厨房 | 新推理 |
| 8 | 同一客厅图片，另一条生成相机轨迹 | 新推理；相机条件变体 |
| 9 | 同一音响房间图片，增加未知区域木质声学墙板补全要求 | 新推理；文本条件变体 |

总计 **10 个展示案例、8 张不同来源图片**，不称为 10 个独立场景。当前已有 2 个成功视频，尚需 8 个新结果；计划数不等于已完成数。6 个开发样本沿用冻结清单，12 个保留测试样本不参与展示开发。

同一张案例卡后续补充第二模型的输出。第二模型尚未接入，本版不会生成虚假的第二模型视频。网页播放预生成 MP4；所有失败和原始产物保留。对比阶段记录各模型接口和轨迹适配差异。

## 2. 相机与文本约定

六张开发图没有标定相机。初版展示使用官方样例 3 的 24 个相机位姿、最终图像内参和 image_index=3，作为**统一假设模板**，不是新图片的真实相机，也不实现原 WorldScore 的符号动作。

目标尺寸为 704×480。输入保留原字节，上游执行中心裁剪与缩放；封装反算输入内参，使该变换后的内参恰好等于模板内参。完整裁剪参数、原始图像摘要、来源、假设相机标记保存在输入 JSON 的 `_showcase` 字段中。相机位置不解释为米制测量，不能据此计算与真实相机参考帧对齐的像素指标。

索引 8 使用官方样例 5 的位姿轨迹和 image_index=9，保留客厅样例 3 的内参、图片、文本和种子。这是改变相机条件后重新生成，**不是从同一个已保存三维资产换轨迹渲染**，不能据此证明同一资产的跨视角一致性。

索引 9 保持音响房间图片、相机、种子不变，只改变用户文本：

> A room with sound equipment. Keep the visible sound equipment and room layout unchanged. Extend warm wooden acoustic wall panels into newly revealed areas while keeping the floor space unobstructed.

这是未知区域补全请求；模型是否遵循要求属于实验结果，不保证精确风格编辑。输入区域保持与补全要求满足情况分别记录。

先确认上述假设相机协议，再运行索引 2 试跑；若结果出现明显畸变，先调整开发协议并另记版本，不批量生产其余案例。展示视频总时长、轨迹和模型生成耗时分别标注。

## 4. 服务器导入、校验

旧版本的任务结束后再刷新共享资产回执，避免不同版本交替校验同一个回执。

```bash
(
  set -euo pipefail
  cd /shared/your_user/releases
  sha256sum -c world_scene-v0.2.0.tar.gz.sha256
  if [[ ! -e world_scene-v0.2.0 ]]; then
    tar -xzf world_scene-v0.2.0.tar.gz
  fi
  cd world_scene-v0.2.0
  # 依赖未变，显式复用已跑通的环境。
  if [[ ! -e local.env ]]; then
    printf '%s\n' \
      'export SCENE_ENV=/shared/your_user/envs/world-scene-0.1.1' \
      'export MAX_JOBS=2' > local.env
  fi
  unset SCENE_ENV SCENE_RUNS SCENE_LOGS SCENE_STATE PYTHON_BIN
  source slurm/config.sh
  python3 -B tools/experiment.py inspect
  # 版本号改变使整个锁文件摘要变化，需要完整校验刷新回执。
  "$PYTHON_BIN" -B tools/assets.py verify --root "$SCENE_ASSETS" --group models
  python3 -B tools/showcase.py verify --assets "$SCENE_ASSETS" --array '2-9%1'
  "$PYTHON_BIN" -B tools/experiment.py preflight
)
```

六张图片分别与仓库中的冻结摘要比较，不需要重新下载或解压 WorldScore 全量数据。本版不新增 Python 依赖。

## 5. 先试跑一例

在服务器执行；先确认假设相机协议。`SHOWCASE_ARRAY` 的索引对应第 1 节表格，`%1` 限制最多一个同时运行，`MAX_JOBS=2` 是编译并行度。

```bash
cd /shared/your_user/releases/world_scene-v0.2.0
unset SCENE_ENV SCENE_RUNS SCENE_LOGS SCENE_STATE PYTHON_BIN
source slurm/config.sh
squeue -u "$USER"

if MEM=96G CPUS=8 MAX_JOBS=2 SEED=0 DEPENDENCY= \
  SHOWCASE_ARRAY='2%1' bash slurm/submit.sh showcase; then
  PILOT_JOB=$(cat "$SCENE_STATE/showcase.jobid")
  printf '%s\n' "$PILOT_JOB" > "$SCENE_STATE/showcase-pilot.jobid"
  printf '试跑数组号：%s\n' "$PILOT_JOB"
  bash slurm/logs.sh "$PILOT_JOB"
else
  printf '%s\n' '提交失败；不读取旧作业号。'
fi
```

断线重连先 cd/source，再读取 `showcase-pilot.jobid`。任务在排队时可能尚无日志，稍后重新执行 `logs.sh`，不要重复提交。

```bash
PILOT_JOB=$(cat "$SCENE_STATE/showcase-pilot.jobid")
sacct -S 2026-10-20 -j "$PILOT_JOB" \
  --format=JobID%24,State%24,ExitCode,Elapsed,ReqMem,MaxRSS,NodeList
cat "$SCENE_RUNS/showcase-02-$PILOT_JOB-2/manifest.json"
```

试跑完成后按第 7 节的单例导出下载，查看视频；确认输入物体保持、轨迹合理，再运行其余 7 个。不要仅凭退出码成功就认定相机策略适合所有新图。

## 6. 运行其余七个与监控

```bash
if MEM=96G CPUS=8 MAX_JOBS=2 SEED=0 DEPENDENCY= \
  SHOWCASE_ARRAY='3-9%1' bash slurm/submit.sh showcase; then
  GALLERY_JOB=$(cat "$SCENE_STATE/showcase.jobid")
  printf '%s\n' "$GALLERY_JOB" > "$SCENE_STATE/showcase-rest.jobid"
  printf '其余案例数组号：%s\n' "$GALLERY_JOB"
  bash slurm/logs.sh "$GALLERY_JOB"
else
  printf '%s\n' '提交失败；不读取旧作业号。'
fi
```

旧作业每例约一小时仅作预算参考，新图及变体耗时尚未实测。单并发还需加上排队时间。每任务单卡、96G、8 CPU、默认限时 4 小时。

```bash
GALLERY_JOB=$(cat "$SCENE_STATE/showcase-rest.jobid")
squeue -r -j "$GALLERY_JOB"
sacct -S 2026-10-20 -j "$GALLERY_JOB" \
  --format=JobID%24,State%24,ExitCode,Elapsed,ReqMem,MaxRSS,NodeList
bash slurm/logs.sh "$GALLERY_JOB"
```

`logs.sh` 跟踪调用时已有的日志；新数组元素启动后重跑查看命令。Ctrl+C 退出查看，不取消作业。GPU 监控为 `$SCENE_LOGS/gpu-数组号-索引.csv`。失败仅重提失败索引，例如 `SHOWCASE_ARRAY='4%1'`；记录新的数组号和结果目录，导出时采用实际完成的路径。

## 7. 导出与下载

服务器导出试跑案例：

```bash
PILOT_JOB=$(cat "$SCENE_STATE/showcase-pilot.jobid")
"$PYTHON_BIN" -B tools/export_results.py \
  --runs "$SCENE_RUNS" --logs "$SCENE_LOGS" \
  --names "showcase-02-$PILOT_JOB-2" \
  --output "$DATA_ROOT/exports/world_scene-v0.2.0-pilot-$PILOT_JOB.tar.gz"
```

其余七例全部完成后导出，保留与试跑独立的归档：

```bash
GALLERY_JOB=$(cat "$SCENE_STATE/showcase-rest.jobid")
"$PYTHON_BIN" -B tools/export_results.py \
  --runs "$SCENE_RUNS" --logs "$SCENE_LOGS" \
  --names "showcase-03-$GALLERY_JOB-3" "showcase-04-$GALLERY_JOB-4" \
          "showcase-05-$GALLERY_JOB-5" "showcase-06-$GALLERY_JOB-6" \

          "showcase-09-$GALLERY_JOB-9" \

```

原两个案例继续使用已有 `world_scene-v0.1.3-two-indoor-70387.tar.gz`，不把旧版本结果改写为新版本。

在本地 WSL 下载任一归档，输入完整文件名，例如 `world_scene-v0.2.0-pilot-实际数组号.tar.gz`：

```bash
(
  set -euo pipefail
  cd /path/to/project
  read -r -p '输入导出归档文件名：' SCENE_ARCHIVE
  [[ "$SCENE_ARCHIVE" =~ ^world_scene-v0\.2\.0-(pilot|rest)-[0-9]+\.tar\.gz$ ]]
  mkdir -p 实验结果
  rsync -av --partial --progress -e 'ssh -p 22' \
    "your_user@your.cluster.example:/shared/your_user/exports/$SCENE_ARCHIVE*" \
    实验结果/
  cd 实验结果
  sha256sum -c "$SCENE_ARCHIVE.sha256"
  mkdir -p "${SCENE_ARCHIVE%.tar.gz}"
  tar -xzf "$SCENE_ARCHIVE" -C "${SCENE_ARCHIVE%.tar.gz}"
)
```

## 8. 清理与记录

正常任务退出自动清理自己的临时目录。保留原始资产、失败记录、已发布版本和验证过的归档。只有确需清理遗留任务临时目录时执行：

```bash
squeue -u "$USER"
python3 -B tools/cleanup.py --assets "$SCENE_ASSETS"
# 先核对候选；当前用户无排队或运行作业时才执行：
python3 -B tools/cleanup.py --assets "$SCENE_ASSETS" --apply
```

本版未创建多余训练 checkpoint，无需删除旧权重或环境。10 个案例逐个记录状态与视觉缺陷；达到 10 个可展示结果需要实际完成验收，失败不会因属于展示计划而被改成成功。
