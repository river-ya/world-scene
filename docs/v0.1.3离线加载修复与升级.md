# v0.1.3：离线加载修复、升级与 Slurm 重提

日期：2026-10-19。适用于 v0.1.2 作业 69914 在加载 Wan Transformer 分片时出现 `OfflineModeIsEnabled` 的情况。

## 1. 本次错误与修复

69914 已通过 GPU/BF16/gsplat、模型资产 quick 校验和 tokenizer 初始化，并加载完文本编码器的三个分片。失败发生在 Diffusers 使用 repo ID 加载 Transformer 时调用 `model_info` 查询远端。日志没有报告主存或 CUDA OOM；`torch_dtype` 弃用和 SageAttention 缺失提示不是此次退出原因。

锁定版本的 [Diffusers 分片解析实现](https://github.com/huggingface/diffusers/blob/447e8322f76efea55d4769cd67c372edbf0715b8/src/diffusers/utils/hub_utils.py) 对本地目录直接解析文件；使用 repo ID 且未显式传 local_files_only 时会调用远端元数据接口。只设置 HF_HUB_OFFLINE 会拦截该调用，不能保证每个调用方自动转为本地路径。

v0.1.3 在项目封装中将固定 Wan 仓库的加载请求转换为锁定 revision 的本地快照路径，显式传入 local_files_only=True。覆盖 VAE、tokenizer、文本编码器、Transformer 和 scheduler 的加载；保留 dtype、subfolder 等原参数。只在上游运行期间作用，退出恢复原方法，不修改上游子模块、模型结构、权重、分辨率或精度。

smoke/batch/ui 的提交入口先在登录节点执行 CPU preflight，检查资产回执、tokenizer 编码、各组件配置以及 5 个 Transformer / 3 个文本编码器分片路径。不加载大模型权重，不使用 GPU，不代表完整推理成功。

## 2. 本地上传新源码包

## 4. 刷新校验回执并做 CPU 预检

这一步是必须的：版本号变更改变了整个锁文件摘要，旧版回执会失效。完整 verify 只读取已有文件，生成新版本回执，不下载、不加载模型；数十 GB 文件校验时间取决于共享磁盘速度。不要同时运行其他版本的完整校验。

```bash
"$PYTHON_BIN" -B tools/assets.py verify --root "$SCENE_ASSETS" --group models
```

看到资产校验通过后执行：

```bash
CUDA_VISIBLE_DEVICES='' "$PYTHON_BIN" -B tools/experiment.py preflight
```

必须出现 `OFFLINE_PREFLIGHT_OK`，并显示本地固定快照和 `transformer: 5`、`text_encoder: 3`。该命令始终开启离线模式；失败时保留完整错误，不需要先排 GPU 队列。

完整验证不是绕过摘要检查。若 verify 报文件缺失或摘要不符，处理对应文件后再继续。后续使用 WorldScore 时另对 worldscore 组刷新回执。

## 5. 提交 64G smoke 与实时查看

69914 已失败，无需取消。先检查当前是否还有同一实验在运行或排队；若有，避免重复提交。仍使用 GPU1、debug、stu、normal，不移除未知来源的节点权限/排除限制。

```bash
squeue -u "$USER"
if MEM=64G CPUS=8 MAX_JOBS=2 DEPENDENCY= bash slurm/submit.sh smoke; then
  SMOKE_JOB=$(cat "$SCENE_STATE/smoke.jobid")
  printf '新 smoke 作业号：%s\n' "$SMOKE_JOB"
  scontrol show job "$SMOKE_JOB"
  bash slurm/logs.sh "$SMOKE_JOB"
else
  printf '%s\n' '预检或提交失败；停止，不读取旧作业号。'
fi
```

提交脚本会自动再做一次轻量 preflight。检查 ReqTRES 为 mem=64G、Dependency=(null)。smoke 自身还会做 GPU 检查，因此无须依赖可能过期的 CHECK_JOB。CPU 预检通过不意味着完整模型能装入 64G，后续是否 OOM 仍需实测；不要仅凭本次离线错误加到 96G。

队列为空或 scontrol 查不到时，不代表成功，使用 sacct 和具体 job ID 日志。Ctrl+C 只退出 tail，不取消作业。另一个集群终端监控：

```bash
cd /shared/your_user/releases/world_scene-v0.1.3
unset SCENE_ENV SCENE_RUNS SCENE_LOGS SCENE_STATE PYTHON_BIN
source slurm/config.sh
SMOKE_JOB=$(cat "$SCENE_STATE/smoke.jobid")
squeue --start -j "$SMOKE_JOB"
sacct -S 2026-10-19 -j "$SMOKE_JOB" \
  --format=JobID,JobName,State,ExitCode,Elapsed,ReqMem,MaxRSS,NodeList
tail -n 120 "$SCENE_LOGS"/smoke-"$SMOKE_JOB"_*.err
tail -n 80 "$SCENE_LOGS"/smoke-"$SMOKE_JOB"_*.out
```

GPU 监控文件在 GPU/资产检查通过后创建：

```bash
tail -n 20 -F "$SCENE_LOGS/gpu-$SMOKE_JOB-0.csv"
```

完成后检查实验记录，新的 manifest 包括 `wan_snapshot` 和 `model_loading=pinned_local_snapshot`：

```bash
cat "$SCENE_RUNS/room_b1-$SMOKE_JOB-0/manifest.json"
```

只有 status=complete 表示自动推理检查通过；仍需人工查看 PLY/SPZ 的三维质量。失败作业保留日志和 manifest。本版是生成推理，没有训练 loss 或训练 checkpoint。

## 7. 清理与回滚

新代码解压在独立版本目录。保留旧版本、环境、权重、下载断点、失败实验及日志，不删除其他项目的缓存。任务正常退出会自动清理自己的临时目录。

所有当前用户作业结束后，在集群新版本目录预览并清理遗留临时文件：

```bash
squeue -u "$USER"
python3 -B tools/cleanup.py --assets "$SCENE_ASSETS"
# 核对候选且当前用户没有排队/运行作业后：
python3 -B tools/cleanup.py --assets "$SCENE_ASSETS" --apply
```

如果回到旧版本，先清除继承的 SCENE_RUNS/SCENE_LOGS/SCENE_STATE 等目录变量并 source 旧配置，再按旧锁文件完整 verify 更新其回执；共享回执不能同时服务不同锁文件。旧版仍存在已知离线加载问题，不建议直接重复提交来验证本修复。
