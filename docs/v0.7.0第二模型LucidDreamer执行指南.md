# v0.7.0：LucidDreamer 第二模型完整执行指南

本版接入 **SNU CVLab 的 LucidDreamer**：单张 RGB＋文本生成三维高斯场景，交付 PLY、MP4 和逐视角 PNG。先运行 GPU 检查、studio 单例，再运行其余共同案例。当前 FlashWorld 作业继续使用原版本，本版不改它的环境、权重回执或结果。

状态：代码与本地检查见 [验证记录](v0.7.0本地验证记录.md)。本地 GPU 只有 4GB，未在 4090 上完成真实模型推理；集群 check 和首例视觉验收是必需步骤，不将本地测试写成 GPU 成功。

## 1. 任务、模型及适配范围

选型依据：[LucidDreamer 论文](https://arxiv.org/abs/2311.13384)、[作者实现](https://github.com/luciddreamer-cvlab/LucidDreamer)、[FlashWorld 同任务比较](https://arxiv.org/html/2510.13678v1#S4.SS3)。LucidDreamer 源码固定 `4ddf48563140c4254c8ce566955d12531b46829c`，MiDaS 固定 v3_1，源码/权重清单独立为 `configs/lucid.lock.json`。源代码适配明细见 [适配说明](LucidDreamer适配说明.md)。

- 使用与现有 FlashWorld 案例相同的图片、完整文本、704×480 裁剪结果及内参，取消 LucidDreamer 默认的宽图补成方图行为。不会用空文本替代现有文本。
- 保留每例自己的目标轨迹，支持原 room、studio、room_short、studio_mirrored。输入图是 LucidDreamer 第一个生成视角；输出视频恢复原轨迹顺序，原 room 输入锚点约 3 秒，其余约 9 秒。
- 相机统一为输入锚点局部坐标，并使用与 FlashWorld 相同的平移归一化分母；保留 ZoeDepth 自身预测深度。**跨模型几何的绝对尺度尚未标定**。这是共同图文/内参/数值轨迹的定性对照，不能宣称同一真实米制轨迹上的严格排名。
- 使用原始 SD inpainting、ZoeDepth 和 2990 步逐场景高斯优化，SD 补图 50 步，seed 0。`GS_ITER ... loss=...` 是当前场景高斯优化，不是扩散模型微调。
- 本版显式使用完整三维资产重载后渲染视频。不同算法的生成视图顺序和内部优化视图数有差别，计入耗时，不把这些内部视图冒充额外真实输入。

| 索引 | 场景 | 对应 FlashWorld 条件 |
|---|---|---|
| 0 | 官方 room_b1 | 原 70288，原 room 完整路径（后段转角较大） |
| 1 | 官方 studio_b1 | 原 70387，原 studio 路径；**先跑这一例** |
| 2 | 第一张新厨房 | 原 70754，完整 studio 路径 |
| 3 | 客厅/餐区 | v0.6.0 room_short |
| 4 | 废弃走廊 | studio |

| 8 | 官方客厅相机变体 | studio |
| 9 | 官方 studio 文本变体 | studio，相同变体文本 |

若正在运行的 FlashWorld 是 v0.5.0，3/5/6/7 的轨迹与本版不同，不能直接作同轨迹对照。应与 v0.6.0 对应输出比较，或使用每个新结果的 `inputs/flashworld.json` 另建成对运行。当前十例仍来自八张源图，12 张冻结测试图不参与试调。

## 4. 服务器登录节点：安装环境与下载资产

这一步只安装/编译和下载，不执行模型推理。需要能访问 Conda、PyPI、PyTorch、Hugging Face 和 GitHub。环境包含 Python 3.9、PyTorch 2.0.1 cu118、独立 CUDA 11.8 编译器和 GCC/G++ 11，不修改系统 CUDA 或 FlashWorld 环境。安装、模型文件及缓存建议预留至少 25GB 磁盘。

长时间安装建议在 tmux 中执行，断线后用 `tmux attach -t lucid-setup` 恢复；不要同时运行两个安装进程。

```bash
tmux new -s lucid-setup
```

在 tmux 内执行下面整个括号块。成功后 `Ctrl+B` 再按 `D` 脱离，不会终止工作。若没有 tmux，直接运行也可以，但断线中断后需重新执行同一步。

```bash
(
  set -euo pipefail
  cd /shared/your_user/releases/world_scene-v0.7.0
  source slurm/lucid/config.sh
  mkdir -p "$LUCID_LOGS"
  bash slurm/lucid/create_env.sh 2>&1 | tee "$LUCID_LOGS/setup.log"
  unset HF_HUB_OFFLINE TRANSFORMERS_OFFLINE
  "$LUCID_PYTHON" -B tools/lucid_assets.py download --root "$LUCID_ASSETS" \
    2>&1 | tee "$LUCID_LOGS/download.log"
  "$LUCID_PYTHON" -B tools/lucid_assets.py verify --root "$LUCID_ASSETS"
  "$LUCID_PYTHON" -B tools/lucid.py preflight --array '0-2%1'
)
```

成功末尾应出现 `LUCID_OFFLINE_PREFLIGHT_OK` 和三个 `LUCID_INPUT_OK`。SD 权重使用固定 revision、本地 fp16 safetensors；旧仓库的 `revision=fp16` 已不可用，本版不用该分支。ZoeDepth 取作者固定 release URL：首次下载记录 SHA256，之后拒绝摘要改变；该摘要不是作者预公布的校验值。其余 SD 文件对照 HF 固定 revision 元数据验证。

下载可续传。若下载失败，重新执行 download/verify，不删除已下载权重，也不解除计算节点的离线模式。环境脚本编译目录正常退出或失败时自动清理，下载的 `.part` 保留用于恢复。

若创建环境途中中断，重试提示编译器不完整，仅修复这个独立环境：

```bash
(
  set -euo pipefail
  cd /shared/your_user/releases/world_scene-v0.7.0
  source slurm/lucid/config.sh
  conda install -y --prefix "$LUCID_ENV" --override-channels \
    -c nvidia/label/cuda-11.8.0 -c conda-forge \
    python=3.9 pip cuda-toolkit=11.8 gcc_linux-64=11 gxx_linux-64=11
  bash slurm/lucid/create_env.sh
)
```

有 LucidDreamer 作业正在运行时不要重装其环境。正在运行的 FlashWorld 使用另一环境，不受此环境安装影响。

## 5. 提交实际 GPU 检查

检查包括 CUDA KNN、真实高斯栅格化前向/反向、加载完整 SD/ZoeDepth、一次深度推理及两步补图。它不是完整场景生成。先请求 **32G 主机内存、4 CPU、1 张 4090、45 分钟**。32G 是检查预算，不等于显存；推理预算尚待实测。

```bash
cd /shared/your_user/releases/world_scene-v0.7.0
source slurm/lucid/config.sh
if LUCID_MEM=32G LUCID_CPUS=4 LUCID_ARRAY='1%1' LUCID_DEPENDENCY= \
  bash slurm/lucid/submit.sh check; then
  LUCID_CHECK_JOB=$(cat "$LUCID_STATE/check.jobid")
  printf '检查作业号：%s\n' "$LUCID_CHECK_JOB"
  squeue -j "$LUCID_CHECK_JOB"
  bash slurm/lucid/logs.sh "$LUCID_CHECK_JOB"
else
  echo '预检或提交失败，不读取旧作业号。'
fi
```

等待结束后验证，不要只看队列消失：

```bash
cd /shared/your_user/releases/world_scene-v0.7.0
source slurm/lucid/config.sh
LUCID_CHECK_JOB=$(cat "$LUCID_STATE/check.jobid")
sacct -S 2026-10-22 -j "$LUCID_CHECK_JOB" \
  --format=JobID%24,State%24,ExitCode,Elapsed,ReqMem,MaxRSS,NodeList
tail -n 100 "$LUCID_LOGS"/check-"$LUCID_CHECK_JOB"_*.err
tail -n 80 "$LUCID_LOGS"/check-"$LUCID_CHECK_JOB"_*.out
cat "$LUCID_RUNS/check-$LUCID_CHECK_JOB/manifest.json"
```

要求 Slurm 为 `COMPLETED`、退出码 `0:0`、manifest 为 `complete`，日志含 `LUCID_GPU_CHECK_OK`。检查图片仅验证计算链路，不用来评价完整生成质量。

## 6. studio 单例试跑

只有 check 成功后执行。先用 **64G 主机内存、8 CPU、1 张 4090、8 小时上限**，默认单并发。这是保守试跑预算，尚未测得本项目耗时或峰值，不沿用 FlashWorld 的一小时结论。`LUCID_DEPENDENCY=` 清空依赖，避免完成很久的作业号被 Slurm 清除后导致提交失败。

```bash
cd /shared/your_user/releases/world_scene-v0.7.0
source slurm/lucid/config.sh
if LUCID_MEM=64G LUCID_CPUS=8 LUCID_TIME=08:00:00 \
  LUCID_ARRAY='1%1' LUCID_DEPENDENCY= bash slurm/lucid/submit.sh run; then
  LUCID_JOB=$(cat "$LUCID_STATE/run.jobid")
  printf '%s\n' "$LUCID_JOB" > "$LUCID_STATE/pilot.jobid"
  printf 'studio 试跑作业号：%s\n' "$LUCID_JOB"
  scontrol show job "$LUCID_JOB"
  bash slurm/lucid/logs.sh "$LUCID_JOB"
else
  echo '预检或提交失败，不读取旧作业号。'
fi
```

`PD (Resources)` 是资源等待，`PD (None)` 可短暂出现，不等于执行失败。脚本默认 GPU1；只有确认其他节点的卡型和使用权限满足要求后，才通过 `LUCID_NODE` 改节点，不在本版自动扩大节点范围。


只查看某例最近日志及结果状态，例如 studio 索引 1：

```bash
LUCID_INDEX=1
LUCID_JOB=$(cat "$LUCID_STATE/case-$LUCID_INDEX.jobid")
LUCID_NAME=$(printf 'lucid-%02d-%s-%s' "$LUCID_INDEX" "$LUCID_JOB" "$LUCID_INDEX")
tail -n 100 "$LUCID_LOGS/run-${LUCID_JOB}_${LUCID_INDEX}.err"
tail -n 100 "$LUCID_LOGS/run-${LUCID_JOB}_${LUCID_INDEX}.out"
tail -n 10 "$LUCID_LOGS/gpu-$LUCID_JOB-$LUCID_INDEX.csv"
cat "$LUCID_RUNS/$LUCID_NAME/manifest.json"
```

尚未启动时文件可能不存在。正常完成后 `outputs/gaussians.ply`、`outputs/video.mp4`、`outputs/view-00.png` 至 `view-23.png` 必须存在，manifest 为 `complete`；仍需检查视频质量。若被 Slurm OOM/SIGKILL 强杀，Python 来不及更新 manifest，可能停留 `running`，此时以 sacct/err 判定失败，不能导出为成功。

## 10. 清理无用临时文件

安装编译目录和正常退出作业的 TMPDIR 自动删除。为避免误删正在运行的 FlashWorld/LucidDreamer 数组，清理工具在当前用户仍有任何作业时拒绝 apply。全部任务结束后，先看候选，再执行限定范围删除：

```bash
cd /shared/your_user/releases/world_scene-v0.7.0
source slurm/lucid/config.sh
squeue -u "$USER"
python3 -B tools/cleanup.py --assets "$LUCID_ASSETS"
# 仅在队列为空，并确认候选是无用作业临时目录后执行：
python3 -B tools/cleanup.py --assets "$LUCID_ASSETS" --apply
```

保留权重、环境、源码发布、下载回执、成功及失败结果、输入快照和导出归档。不要执行全局 `conda clean`、删除共享模型缓存，或删除正在使用的旧版本。没有必要通过清空全部文件来升级第二模型。
