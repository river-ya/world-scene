# v0.6.0 剩余案例：三种相机轨迹

用户要求“别统一使用相机模板，可以多点变化”。本版按展示案例分配三种运动路径，图文、seed 0、权重、精度、分辨率与 offload 保持。原 studio 路径已在 70754 获用户认可；两种新派生路径仅完成几何/CPU 检查，GPU 效果待验证。

## 1. 轨迹与案例分配

| 索引 | 场景 | 本版轨迹 | 最大相对转角 |
|---|---|---|---|
| 3 | 客厅/餐区 | room_short：官方 room 前 12 个相机组成的曲线，重采样 24 帧 | 约 30.28° |
| 4 | 废弃走廊 | studio：原 studio 路径 | 约 26.85° |
| 5 | 图书馆 | studio_mirrored：相对输入相机向另一侧运动并转向 | 约 26.85° |
| 6 | 办公室 | room_short：room 前段曲线 | 约 30.28° |
| 7 | 另一厨房 | studio_mirrored：反侧路径 | 约 26.85° |
| 8 | 原客厅相机变体 | studio：原 studio 路径 | 约 26.85° |
| 9 | 原 studio 文本变体 | studio：保持原相机，只改变文本 | 约 26.85° |

- `room_short` 只用官方 room 索引 0–11 的轨迹，避开后段约 143° 的大转向。平移线性插值、旋转 SLERP；原 room 输入相机 index 3 映射到新 index 9。使用 room 目标内参。
- `studio_mirrored` 在输入相机的局部坐标中反射相机路径：横向位置换侧，旋转以 SRS 变换保持合法旋转。图片和文字不翻转，也不是倒放同一个视频；新方向会暴露不同区域。使用 studio 目标内参。
- `studio` 保留固定官方 examples/5.json 原始轨迹。索引 9 保留这一设置，确保文本变体仍是文本对照。

三个 profile 都是 24 个相机、704×480、index 9、原生归一化；输入对应视频约第 9 秒。原生归一化后的最大锚点距离分别约 0.698（room_short）和 0.557（两种 studio），不是米/厘米。不存在 5° 的小范围限制，但也不能保证所有新视角无破洞。

已认可的 70288、70387、70754 保留。不同场景采用不同轨迹是展示设计，不能把这些结果直接当作统一相机条件下的模型排名；后续模型比较须给各模型使用同一案例的相同图文和轨迹。模型/数据选择沿用既有论文依据，不增加模型、权重或测试集。

## 4. 按需提交，默认单并发

使用 v0.6.0 的 `gallery` 入口。每例一张 4090、96G、8 CPU、上限 4 小时；`%1` 最多同时一个，`MAX_JOBS=2` 是编译并行度。

提交前查看队列与旧版状态：如果 v0.5.0 尚未提交，选择 `3-9%1`；如果旧版已提交或完成，可保留其中相机没有变化的 4、8、9，只运行变化的 `3,5-7%1`。已运行任务不取消，原结果不删除。共享回执在旧作业结束后刷新；不要同时运行两个版本并交替刷新回执。

```bash
cd /shared/your_user/releases/world_scene-v0.6.0
unset SCENE_ENV SCENE_RUNS SCENE_LOGS SCENE_STATE PYTHON_BIN
source slurm/config.sh
squeue -u "$USER"
# 二选一；根据旧版是否已提交选择，不要连续执行两种提交。
GALLERY_SELECTION='3-9%1'
# GALLERY_SELECTION='3,5-7%1'
SCENE_INDICES=$(python3 -B -c 'import sys; sys.path.insert(0,"tools"); from gallery import task_indices; print(" ".join(map(str,task_indices(sys.argv[1]))))' "$GALLERY_SELECTION")

if MEM=96G CPUS=8 MAX_JOBS=2 SEED=0 DEPENDENCY= \
  GALLERY_ARRAY="$GALLERY_SELECTION" bash slurm/submit.sh gallery; then
  GALLERY_JOB=$(cat "$SCENE_STATE/gallery.jobid")
  printf '%s\n' "$GALLERY_JOB" > "$SCENE_STATE/gallery-main.jobid"
  printf '%s\n' "$GALLERY_SELECTION" > "$SCENE_STATE/gallery-selection.txt"
  for SCENE_INDEX in $SCENE_INDICES; do
    printf '%s\n' "$GALLERY_JOB" > "$SCENE_STATE/gallery-$(printf '%02d' "$SCENE_INDEX").jobid"
  done
  printf '本批主数组号：%s\n' "$GALLERY_JOB"
  squeue -r -j "$GALLERY_JOB"
  bash slurm/logs.sh "$GALLERY_JOB"
else
  printf '%s\n' '预检或提交失败，不读取旧作业号。'
fi
```

70754 包含模型加载约 63 分钟，七例串行可按约 7–8 小时、仅四个变化案例约 4–5 小时，再加排队时间作预算，实际以运行记录为准。无需全程保持 SSH；不需要重新提交 check，也不使用过期依赖号。排队时无日志是正常情况，不要重复提交主数组。

## 6. 仅重提实际失败索引（可选）

以下仅举例：只有 5、7 失败且确需重试时才执行；若失败的是其他索引，数组参数和循环中的数字必须同步替换。新作业不覆盖旧失败结果，`gallery-main.jobid` 保留主数组号，单例状态记录实际重试数组号。

```bash
if MEM=96G CPUS=8 MAX_JOBS=2 SEED=0 DEPENDENCY= \
  GALLERY_ARRAY='5,7%1' bash slurm/submit.sh gallery; then
  GALLERY_RETRY_JOB=$(cat "$SCENE_STATE/gallery.jobid")
  for SCENE_INDEX in 5 7; do
    printf '%s\n' "$GALLERY_RETRY_JOB" > "$SCENE_STATE/gallery-$(printf '%02d' "$SCENE_INDEX").jobid"

```

若只是画面不好而执行成功，保留缺陷记录；同种子原样重跑不作为质量修复办法。

## 7. 本批完成后在服务器导出

按本次选择的索引和每例状态文件构造真实路径，支持部分任务用新数组号重试。本批全部 `complete` 且产物摘要通过才会导出；不覆盖已有同名归档。若复用了 v0.5.0 的 4、8、9，按后面的单独命令导出其原版本结果，不混写为 v0.6.0。

```bash
(
  set -euo pipefail
  cd /shared/your_user/releases/world_scene-v0.6.0
  unset SCENE_ENV SCENE_RUNS SCENE_LOGS SCENE_STATE PYTHON_BIN
  source slurm/config.sh
  GALLERY_MAIN_JOB=$(cat "$SCENE_STATE/gallery-main.jobid")
  GALLERY_SELECTION=$(cat "$SCENE_STATE/gallery-selection.txt")
  SCENE_INDICES=$(python3 -B -c 'import sys; sys.path.insert(0,"tools"); from gallery import task_indices; print(" ".join(map(str,task_indices(sys.argv[1]))))' "$GALLERY_SELECTION")
  SCENE_NAMES=()
  for SCENE_INDEX in $SCENE_INDICES; do
    SCENE_CASE=$(printf 'gallery-%02d' "$SCENE_INDEX")
    SCENE_JOB=$(cat "$SCENE_STATE/$SCENE_CASE.jobid")
    [[ "$SCENE_JOB" =~ ^[0-9]+$ ]]
    SCENE_NAMES+=("$SCENE_CASE-$SCENE_JOB-$SCENE_INDEX")
  done
  "$PYTHON_BIN" -B tools/export_results.py \
    --runs "$SCENE_RUNS" --logs "$SCENE_LOGS" --names "${SCENE_NAMES[@]}" \
    --output "$DATA_ROOT/exports/world_scene-v0.6.0-varied-$GALLERY_MAIN_JOB.tar.gz"
)
```

## 8. 本地下载、摘要校验及解压

输入主数组号，即 `gallery-main.jobid` 中的数字，不填重试数组号，也不填完整归档名。

```bash

  rsync -av --partial --progress -e 'ssh -p 22' \
    "your_user@your.cluster.example:/shared/your_user/exports/$SCENE_ARCHIVE" \
    "your_user@your.cluster.example:/shared/your_user/exports/$SCENE_ARCHIVE.sha256" \
```

若本批只运行四个变化案例，归档只含这四例，这是预期行为。每个案例的视频位于解压目录内 `gallery-索引-实际数组号-索引/outputs/gallery-索引/video.mp4`，其中案例名前的索引补零（03–09），末尾任务索引不补零（3–9）。复用旧三例时保留其真实版本与作业身份。

## 9. 验收与清理

逐例记录相机 profile；新前段曲线和反侧轨迹尚待视觉验证，不能沿用 studio 的成功结论。检查约第 9 秒输入锚点的物体/布局保持、全片是否确有新增区域、碎片/穿透/重复物体和闪烁。索引 8 与原 room_b1 对照时，原视频输入锚点约第 3 秒；索引 9 与原 studio 对照时两者都约第 9 秒。文本变体是否改变未知区域是待测结果，不保证精确编辑。

正常退出自动清理本任务临时输入。仅在确需清除异常退出遗留目录时执行下面的候选检查；当前用户有任何排队或运行任务时，清理工具拒绝执行删除。

