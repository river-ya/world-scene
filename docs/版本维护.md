## 记录内容

| 对象 | 记录位置 |
|---|---|
| 项目代码 | Git commit、vX.Y.Z 标签、VERSION |
| 原始基线 | Git 子模块＋versions.lock.json 中源码摘要 |
| 模型和原始数据 | versions.lock.json 的 revision、大小和文件摘要 |
| 数据划分 | configs/data/worldscore-indoor-v1.json，按源图像去重 |
| 实验环境 | 每次运行的 environment.freeze.txt |
| 实验输入/种子/硬件/版本/状态 | 每次运行的 manifest.json、inputs、versions.lock.json |
| 发布包 | RELEASE.json、压缩包及 .sha256 |

版本号采用 X.Y.Z：修复封装或文档增加 Z；改变架构、数据协议或基线增加 Y；改变项目级接口与验收边界增加 X。已发布标签和同版本压缩包不覆盖。更换权重、数据或提示词必须留下新的记录；测试集不得用于调参。

## 日常修改

在本地 Git 仓库中操作；正式实验要求工作区干净。`local.env` 只用于本机路径与队列配置，不提交凭据。不要直接修改上游子模块，需要修补时另建明确记录的补丁或 fork。

```bash
cd /path/to/project/world_scene
git status --short
git switch -c fix/describe-change
# 编辑代码、VERSION 和 CHANGELOG.md；同步 configs/versions.lock.json 的 project_version。
python3 -B -m unittest discover -s tests -v
for SCENE_SCRIPT in slurm/*.sh; do bash -n "$SCENE_SCRIPT" || exit 1; done
git diff --check
git diff
# 只暂存本次核对过的文件；下面列出示例文件。
git add VERSION CHANGELOG.md configs/versions.lock.json
git commit -m 'Describe the verified change'
```

首次自动化建库使用独立的本地自动化提交身份，不修改全局 Git 配置。后续个人提交使用自己的 Git 身份。仓库尚未设置远端；需用户指定远端后再推送，当前具备本地历史和离线备份。

## 发布新版本

在所有改动提交后运行。VERSION、变更记录、锁文件版本及标签应一致；工具拒绝未提交工作区、上游修改和同版本包内容变化。

```bash
SCENE_NEW_VERSION=$(tr -d '\r\n' < VERSION)
git tag -a "v$SCENE_NEW_VERSION" -m "Release v$SCENE_NEW_VERSION"
python3 -B tools/release.py --output ../交付包
# 为本地历史做离线备份；新版本使用新的 bundle 文件名。
git bundle create "../交付包/world_scene-v$SCENE_NEW_VERSION.bundle" --all
git bundle verify "../交付包/world_scene-v$SCENE_NEW_VERSION.bundle"
```

发布包包含固定上游源码，可直接在集群解包运行，无需集群访问 GitHub 克隆源码。Git bundle 保存本项目历史；子模块的源码由发布包保存，重新作为 Git 子模块开发时仍需联网初始化固定提交。

## 集群升级与回滚

完整导入/监控/导出/清理命令见 [Slurm 执行指南](Slurm执行指南.md)。每个版本解压到独立 `releases/world_scene-vX.Y.Z`，使用独立环境、日志、状态和结果目录。不要覆盖正在运行的发布目录或复用环境做未记录升级。v0.1.2 仅修复启动路径，依赖未变，允许按 [升级指南](v0.1.2升级与重提.md) 在 local.env 显式记录并复用 v0.1.1 环境，不在旧环境里安装或升级包。切换版本前清除继承的 SCENE_RUNS/SCENE_LOGS/SCENE_STATE 等变量，避免结果落入旧版目录。回滚时进入旧版目录并提交新的作业，旧结果保持不变。

下载缓存包含 pinned snapshots，但 Hugging Face 的 `refs/main` 是共享可变指针。本版启动前检查其版本；不同模型版本同时运行时，应给新版本设置独立 `SCENE_ASSETS`，不能在老作业运行中切换共享 refs。Quick 校验依赖先做完整摘要校验，在文件拷贝后必须重新执行完整校验。

中断作业可能留下 `status=running` 的记录，需结合 sacct 判断并新增中断说明，不能手动改成成功。失败作业换新名字重跑；保留失败记录用于排查。

## v0.1.3 离线加载兼容层

`tools/offline_models.py` 仅在上游执行期间，将固定 Wan repo ID 重定向为锁定 revision 的本地路径，显式限制本地读取，并在退出时恢复加载方法；上游子模块文件保持摘要一致。相关升级步骤见 [v0.1.3 指南](v0.1.3离线加载修复与升级.md)。版本号改变也会改变整个锁文件摘要，必须完整校验资产来更新旧回执，不能手改回执。依赖版本未变，可显式复用已有 v0.1.1 环境。
