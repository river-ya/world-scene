# v0.8.0 同一张客厅图：30° / 45° / 75° 生成对照

本版新增 `angles` 独立入口，分别进行三次完整 FlashWorld 推理。不是把旧 PLY 换个视角录屏，也没有训练或微调模型。原有 gallery 和第二模型入口不变，旧结果不覆盖。

## 1. 输入、相机及验收目标

输入是已经完成的 `gallery-03-71013-3` 所用客厅/餐区图片，即冻结开发集 `ws-indoor-001`，本地文件 `world_scene_assets/data/worldscore-indoor-v1/images/001.jpg`。仍用原文本、seed 0、704×480、24 个相机、原裁剪与有效内参。

| 数组任务索引 | 生成条件 | 输入/结果名 |
| --- | --- | --- |
| 0 | 从输入方向水平向左转至 30° | angles-living-left-30 |
| 1 | 从输入方向水平向左转至 45° | angles-living-left-45 |
| 2 | 从输入方向水平向左转至 75° | angles-living-left-75 |

三档均固定相机中心，绕输入相机局部竖直轴转向，保持相对输入的俯仰与滚转；这里的水平是相对输入相机，不是未知的真实重力方向。输入锚点改为 index 0，**视频第一帧就是输入视角**；相机采样和 15 fps 视频时间一致，输出 346 帧、约 23 秒。三档之间只改变 yaw 幅度。

纯旋转轨迹的平移范围为零，必须显式使用共同的正参考尺度。代码复用旧 gallery-03 的参考尺度约 3.481835，不允许上游自动推导零尺度；生成、视频和高斯导出使用一致尺度。这个尺度不是米。预检验证实际归一化、密集插值、相机朝向、内参和光线方向。

30° 是同一新轨迹族的基线；旧 room_short 还包含平移、抬头、回转且输入锚点为 9，不能把它直接当成严格角度消融的 30° 条件。纯旋转主要检验视野外补全，不能证明物体背面重建能力；后续横移实验再检查解除遮挡后的结构。

任务依据：WorldScore 强调显式相机控制下的新场景生成，并分别考察控制和质量；FlashWorld 为图文条件下的 3D 场景生成方法。30/45/75 是本项目受控诊断档位，不是论文官方参数，不保证 75° 仍稳定。[WorldScore](https://haoyi-duan.github.io/WorldScore/)、[FlashWorld 论文](https://arxiv.org/html/2510.13678v1)。本实验没有未知区域真值，验收合理性与一致性，不宣称恢复真实未见场景。

## 4. 提交三档串行数组

每个任务 **96G 主存、8 CPU、单张 4090、4 小时时限**；`%1` 限制同时一例，`MAX_JOBS=2` 是编译并行度。原实验 64G 曾在模型加载/量化阶段 OOM，这里不减内存。根据已有每例约一小时的记录，三例暂按 3–4 GPU 小时加排队预算，实际以新任务为准。

以下命令只执行一次。主状态文件已经存在时会阻止误重复提交；失败重试按第 6 节执行。

```bash
(
  set -euo pipefail
  cd /shared/your_user/releases/world_scene-v0.8.0
  unset SCENE_ENV SCENE_RUNS SCENE_LOGS SCENE_STATE PYTHON_BIN
  source slurm/config.sh
  squeue -u "$USER"
  if [[ -e "$SCENE_STATE/angles-main.jobid" ]]; then
    echo '本版已记录主数组，请先按第 5 节查状态；不要重复提交。' >&2
    exit 2
  fi
  if MEM=96G CPUS=8 MAX_JOBS=2 SEED=0 DEPENDENCY= \
    ANGLES_ARRAY='0-2%1' bash slurm/submit.sh angles; then
    ANGLES_JOB=$(cat "$SCENE_STATE/angles.jobid")
    [[ "$ANGLES_JOB" =~ ^[0-9]+$ ]]
    printf '%s\n' "$ANGLES_JOB" > "$SCENE_STATE/angles-main.jobid"
    for ANGLE_INDEX in 0 1 2; do
      printf '%s\n' "$ANGLES_JOB" > "$SCENE_STATE/angles-task-$ANGLE_INDEX.jobid"
    done
    printf '三档主数组号：%s\n' "$ANGLES_JOB"
    squeue -r -j "$ANGLES_JOB"
  else
    echo '预检或提交失败，不读取旧作业号。' >&2
    exit 1
  fi
)
```

默认仍请求 GPU1；有 GPU 空闲但主存不足时会排队。`PENDING` 不代表推理失败，尚无日志也正常。没有指定旧 check 作业依赖，避免已清理作业号引起 dependency problem。各任务开始后会自行运行 GPU 检查。

下面直接读取某一档最近日志，不持续等待；修改 `ANGLE_INDEX=0` 为 1 或 2 可切换。首次排队尚未启动时文件不存在。

## 6. 可选：只重提失败档位

仅在任务确已结束且执行失败时使用。例如只有索引 2（75°）失败，以下仅提交该档；如失败集合不同，只改 `ANGLES_RETRY_SELECTION`，状态索引由代码解析，避免数组号对错档。正常完成但质量差时保留失败视觉证据，同种子原样重跑不视为修复。

```bash
(
  set -euo pipefail
  cd /shared/your_user/releases/world_scene-v0.8.0
  unset SCENE_ENV SCENE_RUNS SCENE_LOGS SCENE_STATE PYTHON_BIN
  source slurm/config.sh
  ANGLES_RETRY_SELECTION='2%1'
  ANGLES_RETRY_INDICES=$(python3 -B -c 'import sys; sys.path.insert(0,"tools"); from angles import task_indices; print(" ".join(map(str,task_indices(sys.argv[1]))))' "$ANGLES_RETRY_SELECTION")
  if MEM=96G CPUS=8 MAX_JOBS=2 SEED=0 DEPENDENCY= \
    ANGLES_ARRAY="$ANGLES_RETRY_SELECTION" bash slurm/submit.sh angles; then
    ANGLES_RETRY_JOB=$(cat "$SCENE_STATE/angles.jobid")
    [[ "$ANGLES_RETRY_JOB" =~ ^[0-9]+$ ]]
    for ANGLE_INDEX in $ANGLES_RETRY_INDICES; do
      printf '%s\n' "$ANGLES_RETRY_JOB" > "$SCENE_STATE/angles-task-$ANGLE_INDEX.jobid"
    done
    printf '重试数组号：%s\n' "$ANGLES_RETRY_JOB"
    squeue -r -j "$ANGLES_RETRY_JOB"
  else
    echo '重试提交失败，保留旧状态记录。' >&2
    exit 1
  fi
)
```

## 9. 如何比较

先核对三档首帧布局和输入保持，再看侧面新增区域的结构衔接、空洞、重影、漂浮与几何截断。三个末帧分别对应 30/45/75°；相同视频时刻不代表相同角度。相同 30° 的对齐时刻：30° 档 23 秒、45° 档约 15.33 秒、75° 档约 9.2 秒。可比较共同视角是否因扩大生成范围而损失质量。

保留 75° 破损结果也有价值；不只挑最好帧，不能把新生成一面空墙直接判为失败，也不能用凭空新增家具数量作为成功标准。当前无平移，尚未测试物体背面及遮挡解除。

LucidDreamer 的 v0.7 gallery 协议仍对应旧轨迹。本版未将新的纯旋转输入接入第二模型入口，不能把旧版第二模型视频与本组三档直接用于公平排名。需后续显式适配共同新协议，而不是给旧入口传同样数组索引（旧索引 0–2 代表不同图片）。
