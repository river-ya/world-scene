# v0.1.1 → v0.1.2：Slurm 启动修复与重提

日期：2026-10-18。适用于已经安装 v0.1.1 环境，check 69680 报 `/var/spool/slurmd/job69680/config.sh: 没有那个文件或目录` 的用户。

## 1. 已确认的问题

69680 在 GPU1 上获得了 1 GPU、4 CPU、16G，随后在 job.sh 第 3 行加载配置时退出；还没有运行 nvidia-smi、Python 或模型。这不是本次主存 OOM 的证据。

Slurm 复制并执行批处理脚本，其他用户文件不会一并复制，见 [官方 sbatch 文档](https://slurm.schedmd.com/sbatch.html)。旧脚本用 BASH_SOURCE 的目录找 config.sh，错误指向 spool；v0.1.2 改用提交时已导出的 SCENE_CODE 绝对路径。check、smoke、batch 和 ui 共用此修复。

不要直接编辑 v0.1.1 发布目录中的 job.sh：现有 RELEASE.json 会拒绝文件摘要变化。新版本独立解包，保留旧日志和源码；模型、数据与依赖没有变化，复用旧环境即可。

## 2. 导入新版本

在本地 WSL/Linux 终端执行，只上传源码包和校验文件：

```bash
cd /path/to/project/交付包
sha256sum -c world_scene-v0.1.2.tar.gz.sha256
rsync -av --partial --progress -e 'ssh -p 22' \
  world_scene-v0.1.2.tar.gz world_scene-v0.1.2.tar.gz.sha256 \
  your_user@your.cluster.example:/shared/your_user/releases/
```

在集群登录终端执行：

```bash
cd /shared/your_user/releases
sha256sum -c world_scene-v0.1.2.tar.gz.sha256
if [ ! -e world_scene-v0.1.2 ]; then
  tar -xzf world_scene-v0.1.2.tar.gz
fi
cd world_scene-v0.1.2
python3 -B tools/experiment.py inspect

# 清除同一终端之前 source 旧配置留下的版本目录变量。
unset SCENE_ENV SCENE_RUNS SCENE_LOGS SCENE_STATE PYTHON_BIN

# 只首次创建，不覆盖已有本机配置；无需重新安装依赖。
if [ ! -e local.env ]; then
  cat > local.env <<'EOF'
export SCENE_ENV=/shared/your_user/envs/world-scene-0.1.1
export MAX_JOBS=2
EOF
fi
source slurm/config.sh
printf 'VERSION=%s\nENV=%s\nLOGS=%s\nSTATE=%s\nRUNS=%s\n' \
  "$SCENE_VERSION" "$SCENE_ENV" "$SCENE_LOGS" "$SCENE_STATE" "$SCENE_RUNS"
test -x "$PYTHON_BIN"
"$PYTHON_BIN" -m pip check
```

应看到版本 0.1.2，环境路径以 0.1.1 结尾，日志、状态、结果路径以 v0.1.2 结尾。若旧环境实际装在其他位置，只修改 local.env 中 SCENE_ENV。日志或环境路径不符时先修正本机配置，不重新安装已验证的依赖。新版本使用独立扩展编译缓存，首次 check 可能重新编译 gsplat。

## 3. 处理旧依赖并提交 check

```bash
squeue -u "$USER" -o '%.18i %.24j %.8T %.30R'
# 仅取消已知的两个旧排队作业；已经结束的 ID 可能提示不存在。
scancel --state=PENDING 69655 69656
```

69680 已失败，无需取消。如果还有后来提交且依赖 69680 的 smoke，先用 `scontrol show job 实际作业号` 核对，再用 `scancel --state=PENDING 实际作业号` 取消；新 smoke 应依赖新的 check。不要取消其他实验。

```bash
MEM=16G CPUS=4 MAX_JOBS=2 DEPENDENCY= bash slurm/submit.sh check
CHECK_JOB=$(cat "$SCENE_STATE/check.jobid")
scontrol show job "$CHECK_JOB"
bash slurm/logs.sh "$CHECK_JOB"
```

核对 `ReqTRES` 为 mem=16G。若不同，检查 local.env 是否写死 MEM/CPUS。没有日志意味着尚在排队，启动后再次运行 logs。Ctrl+C 只结束日志跟踪。check 不加载模型，但 16G 尚未在 GPU 环境测得峰值；不能把本次路径修复当作完整 GPU 验证。

```bash
sacct -j "$CHECK_JOB" \
  --format=JobID,JobName,State,ExitCode,Elapsed,ReqMem,MaxRSS
tail -n 100 "$SCENE_LOGS"/check-"$CHECK_JOB"_*.err
```

成功条件：COMPLETED、ExitCode=0:0，标准输出有“GPU/BF16/实际高斯栅格化检查通过”。新的错误应根据日志处理，不直接加到 96G。发生明确的主存 OOM 可尝试 32G、MAX_JOBS=1；CUDA OOM、依赖错误和编译超时是不同问题。

## 4. smoke 与实时监控

check 成功后执行，使用新 job ID 建立依赖：

```bash
MEM=96G CPUS=8 MAX_JOBS=2 DEPENDENCY="$CHECK_JOB" bash slurm/submit.sh smoke
SMOKE_JOB=$(cat "$SCENE_STATE/smoke.jobid")
scontrol show job "$SMOKE_JOB"
bash slurm/logs.sh "$SMOKE_JOB"
```

96G 是完整模型推理的原始预算，仍可能排队。希望试验较低主存时，将该提交命令改为 MEM=64G；两者选一个执行，不重复提交。64G 未经实测，可能主存不足。若已有待运行的 96G smoke，先取消对应作业，再重提。不能依据 check 用量推断完整模型内存需求。

另开一个集群终端监控：

```bash
cd /shared/your_user/releases/world_scene-v0.1.2
unset SCENE_ENV SCENE_RUNS SCENE_LOGS SCENE_STATE PYTHON_BIN
source slurm/config.sh
SMOKE_JOB=$(cat "$SCENE_STATE/smoke.jobid")
squeue -u "$USER" -o '%.18i %.24j %.8T %.30R'
sstat -j "$SMOKE_JOB.batch" --format=JobID,AveRSS,MaxRSS
tail -n 20 -F "$SCENE_LOGS/gpu-$SMOKE_JOB-0.csv"
```

CSV 在作业通过自身 GPU 检查和模型 quick 校验后创建。可另外执行 `watch -n 5 "squeue -u $USER"` 持续观察队列。当前流程是推理，没有训练 loss。

完成后核对输出：

```bash
sacct -j "$SMOKE_JOB" \
  --format=JobID,JobName,State,ExitCode,Elapsed,ReqMem,MaxRSS
cat "$SCENE_RUNS/room_b1-$SMOKE_JOB-0/manifest.json"
```

只有 manifest 的 `status=complete` 才表示自动推理检查完成；视觉质量仍需查看 PLY/SPZ 和 MP4。GPU1 约 241.7 GiB 主存，无法同时放入四个 96G 任务；先完成单样例，再按实测安排 batch。

## 5. 导出与下载

在集群新版本项目目录执行：

```bash
SCENE_EXPORT="$DATA_ROOT/exports/world_scene-v$SCENE_VERSION-smoke-$SMOKE_JOB.tar.gz"
"$PYTHON_BIN" -B tools/export_results.py \
  --runs "$SCENE_RUNS" --logs "$SCENE_LOGS" \
  --names "room_b1-$SMOKE_JOB-0" --output "$SCENE_EXPORT"
(
  cd "$DATA_ROOT/exports" || exit 1
  sha256sum -c "world_scene-v$SCENE_VERSION-smoke-$SMOKE_JOB.tar.gz.sha256"
)
```

本地 WSL/Linux 下载并核验：

```bash
cd /path/to/project

  "your_user@your.cluster.example:/shared/your_user/exports/world_scene-v0.1.2-smoke-$SCENE_SMOKE_JOB.tar.gz*" 实验结果/
(
  cd 实验结果 || exit 1
  sha256sum -c "world_scene-v0.1.2-smoke-$SCENE_SMOKE_JOB.tar.gz.sha256"
)
```

## 6. 删除无用临时文件

69680 在创建任务临时目录之前退出，不需要清空模型、环境或缓存。保留失败日志及旧发布包以便追溯。所有作业结束后，在集群项目目录执行：

```bash
squeue -u "$USER"
python3 -B tools/cleanup.py --assets "$SCENE_ASSETS"
# 核对候选，且当前用户没有排队/运行任务后：
python3 -B tools/cleanup.py --assets "$SCENE_ASSETS" --apply
```
