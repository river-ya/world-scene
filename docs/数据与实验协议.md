# 数据与实验协议

本项目研究单图、文本和相机条件下的静态三维场景生成。方法依据为 [FlashWorld](https://arxiv.org/abs/2510.13678) 和 [LucidDreamer](https://arxiv.org/abs/2311.13384)，可控场景生成评估参考 [WorldScore](https://arxiv.org/abs/2504.00983)。下述划分和相机范围是本项目的开发协议，不是论文官方评分复现。

## 数据来源与划分

| 来源 | 用途 | 范围 |
| --- | --- | --- |
| FlashWorld 作者示例 | 环境连通、输入与文本条件检查、公开客厅样例 | 官方客厅与 studio 两张源图 |
| WorldScore 室内子集 | 开发与保留测试 | 六张开发图、十二张保留测试图 |

WorldScore 的固定来源、revision、原始 ZIP 摘要、逐图摘要和划分见 [worldscore-indoor-v1.json](../configs/data/worldscore-indoor-v1.json)。选择规则如下：

1. 从官方 static 清单筛选室内、静态、写实条目，并保留 content_list 不改变房间的条目。
2. 按源图像路径去重，在类别间轮询；类别内用固定字符串与图像路径的 SHA256 排序。
3. 前六张作为开发图，后十二张作为保留测试图。不能根据生成效果删换保留测试图。

源图路径不同不等于拥有独立真实空间身份标注，模型训练数据重叠风险仍无法排除。当前展示使用开发图，不构成保留测试集上的泛化结论。

## 十例开发展示

十个案例来自八张源图：两张作者示例与六张开发图。当前 LucidDreamer 相机由 [lucid_cameras.py](../tools/lucid_cameras.py) 固定，统一为相对输入视角的水平转向、固定中心、输入锚点 0、smoothstep 缓动。

| 索引 | 场景 | 转向 |
| --- | --- | --- |
| 0 | room | 左 40° |
| 1 | studio | 右 50° |
| 2 | 第一厨房 | 左 45° |
| 3 | 客厅/餐区 | 左 65° |
| 4 | 走廊 | 左 35° |
| 5 | 图书馆 | 右 60° |
| 6 | 办公室 | 右 55° |
| 7 | 另一厨房 | 左 48° |
| 8 | room 相机变体 | 右 58° |
| 9 | studio 文本与相机变体 | 左 52° |

角度是开发设置，并非论文最优值或真实相机标定。索引 8、9 不计为独立场景，索引 9 同时改变文本和相机，不能作为纯文本消融。固定中心旋转也不足以检验平移视差或遮挡物背面。

WorldScore 原清单的符号相机动作与本项目数值相机轨迹不同。原始 manifest 中的 camera_adapter=pending 保持来源身份，不能据此声称执行了官方动作；实际展示协议和相机保存在每次运行输入中。旧相机实验的结果不得直接与新轨迹混合排名。

## 跨模型对照

公开客厅样例使用相同的裁剪后 RGB、用户文本、内参、24 个生成相机、346 个视频相机、704×480 分辨率、15 fps 和种子整数 0。相机统一不代表预测几何具有相同的物理尺度；两个模型的随机过程也不因种子整数相同而等价。

FlashWorld 保留内部 [Static] 前缀与四步生成；LucidDreamer 保留逐视角补图、ZoeDepth 和高斯优化。相机坐标与半像素映射见 [适配说明](LucidDreamer适配说明.md)，背景统一、阶段耗时和观察结果见 [RESULTS.md](RESULTS.md)。冻结输入和结果摘要见 [paired-room40](../examples/paired-room40/)。

空用户描述的对照仍含输入图片；FlashWorld 内部仍添加 [Static]，因此不能称为完全无文本条件。改变完整相机模板的实验也不能当作单因素转角消融。

## 验证与评价范围

运行记录保存源码与权重身份、实际输入、环境、阶段耗时、资源峰值及输出摘要。调度器成功、manifest complete 和文件完整性只说明技术完成，视觉评价还需检查输入保真、语义合理性、结构衔接、跨视角稳定和失效范围。

未知区域没有真实图像监督，不能把新生成物体等同于恢复了真实房间。PSNR、SSIM、LPIPS 需要对齐的真实视角，不能对任意生成相机直接计分。当前未发布正式 WorldScore 排名，也未完成动态状态预测或物理规律评估。

DL3DV 尚未纳入当前已完成的对照。引入新的多视角数据或评估协议时，需要另行记录来源、访问条款、场景划分和相机对齐方法。
